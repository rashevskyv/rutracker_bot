# Звіт про виконану роботу: Єдине мульти-ключове кешування перекладів (v0.6.87)

## Огляд задачі
Користувач помітив, що кількість звернень до OpenRouter дорівнювала кількості ігор при кожному запиті, тобто переклади синопсисів eShop не використовували єдиний глобальний кеш або робили повторні запити.

---

## Виконані кроки

1. **Єдина функція кешування синопсисів (`translate_eshop_synopsis`)**:
   - У `services/translation.py` реалізовано `translate_eshop_synopsis()`.
   - Зберігає переклад у `data/translations_cache.json` одразу за кількома ключами:
     1. `eshop_title_<назва_гри>`
     2. `eshop_fsid_<id>`
     3. `eshop_hash_<sha256_тексту>`

2. **Прозоре логування роботи кешу**:
   - `⚡ [CACHE HIT] Using cached translation for '<Назва>'` — коли переклад взято з дискового кешу (OpenRouter не викликається взагалі, витрати токенів = 0).
   - `🌐 [CACHE MISS] Requesting translation for '<Назва>' via OpenRouter...` — коли гра зустрілася вперше і потрібен запит до API.

3. **Синхронізація з GitHub Gist**:
   - `data/translations_cache.json` автоматично синхронізується через Gist і зберігається між перезапусками та розгортаннями бота.

4. **Тестування**:
   - Усі 11 тестів проходять паралельно (`pytest -v -n auto`).
