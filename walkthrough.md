# Звіт про виконану роботу: Точна фільтрація за глобальним рангом популярності downloads_rank_i (v0.7.21)

## Огляд задачі
Користувач звернув увагу на скріншоті, що при запиті `/random 3 1-5000 50-300 грн` бот видав гру з популярністю `#21287` замість діапазону `#1-5000`.

---

## Виконані кроки

1. **Причина невідповідності**:
   - Раніше діапазон `1-5000` трактувався як офсет пагінації у списку знайдених знижок Solr, а не як реальний глобальний номер популярності гри на Nintendo Switch (`downloads_rank_i`).
2. **Виправлення**:
   - `services/eshop/eshop_service.py`: додано фільтр `downloads_rank_i:[min TO max]` у Solr-запити.
   - `services/eshop/deal_filter.py`: тепер і запит до Solr, і фінальна валідація в Python суворо перевіряють, щоб поле `downloads_rank` на картці гри (`🔥 Популярність: #XXXX`) точно входило у вказаний діапазон (наприклад, `#180`, `#1524`, `#1297` для запиту `1-5000`).
3. **Тестування**:
   - Запити перевірено на живому Nintendo Store API та з юніт-тестами (`pytest -v -n auto`). Усі 20 тестів пройшли успішно.
